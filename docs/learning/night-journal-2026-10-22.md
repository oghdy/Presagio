3. **P-022 학습 노트.** 단계 0~1 전체를 "왜 이렇게 만들었나" 관점으로 쉬운 말로 정리. 면접 예상 질문 3개 포함.

## 진행 기록 (아래에 시간순으로 추가)

### 밤 1. P-017 마지막 손질 (리뷰어 2차 확인 중)
- 작업자가 main(품질 체크 P-020)을 합치고, `ingest-daily`가 끝날 때 품질 체크를 자동으로 돌리게 연결했어. 체크에서 진짜 문제(fail)가 나오면 명령이 종료 코드 1로 끝나서 나중에 알림을 보낼 수 있어. "체크 건너뛰기" 옵션은 일부러 안 뒀어(조용히 넘어가는 걸 막으려고).
- 왜 이 순서냐면: 두 PR이 같은 파일(README, cli.py)을 건드려서 하나(P-020)를 먼저 합치고, 나중 것(P-017)이 그 위에 올라타야 충돌이 한 번만 나.
- 지금 리뷰어가 "fail이면 1, warn만이면 0, dry-run이면 체크 안 함"을 직접 재현하는 중이야. 통과하면 내가 머지해(네가 위임한 D-041).

### 밤 2. P-017 머지 완료 → 매일 수집 명령이 생겼어
- 리뷰어 2차 확인 통과: 품질 체크에서 진짜 문제가 있으면 종료 코드 1, 참고 수준(warn)이면 0, 미리보기(dry-run)는 외부 호출 0. CI 초록. 네가 위임한 대로 내가 squash 머지했어.
- 이제 명령 세 개가 전부 갖춰졌어: `presagio backfill`(과거 채우기), `presagio ingest-daily`(매일 갱신 + 배당 스냅숏 + 품질 체크), `presagio quality-check`(검사만).
- 리뷰어 메모 하나: 품질 체크가 매일 "warn"만 내는 날이 많을 텐데(예: 배당 매핑 안 된 경기), 단계 6에서 알림을 설계할 때 warn은 모아서 하루 한 번, fail은 즉시로 나누면 좋겠대.

### 밤 3. P-021 시작 — 진짜 데이터를 창고에 채워
- 지금까지는 전부 "샘플 몇 경기"로만 테스트했어. 이번엔 2023-24, 2024-25, 2025-26 세 시즌(정규 + 플레이오프)과 올 시즌을 **실제로 받아서** DB에 넣어.
- 호출 수는 시즌당 일정 1번 + 기록 3번 정도라 수십 번이면 끝나. 1초 간격이라 몇 분이면 돼.
- 끝나면 보고서에 시즌별 경기 수, 홈팀 승률, 평균 총점, "한 번 더 돌려도 행 수가 안 늘어남" 증거, 품질 체크 결과를 적어. 아침에 네가 보고서의 SQL을 그대로 돌려 볼 수 있게 해 둘게.
- 혹시 NBA 쪽에서 차단(403/429)하면 작업자가 즉시 멈추고 나한테 보고해. 그건 네가 깨어나면 같이 봐야 해(간격을 늘릴지).

- (우회) 네가 자는 동안엔 내가 새 세션을 직접 못 띄워(앱이 "사람이 카드를 클릭해야" 한다고 거부). 그래서 CLAUDE.md가 허용한 방법대로 **서브에이전트**(같은 data-engineer 역할, 전용 worktree)에게 P-021을 맡겼어. 결과는 나한테 바로 돌아오고, PR은 똑같이 열려. 리뷰도 같은 방식(reviewer 서브에이전트)으로 할 거야. 차이는 "앱 사이드바에 세션 줄이 안 보인다"는 것뿐이야.
