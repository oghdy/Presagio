# 실험 기록 (Experiments)

> 단계 2부터 ML Engineer가 쓴다. **실패한 실험도 반드시 기록한다.**
> 좋은 결과만 남기면 나중에 같은 실패를 반복하고, 면접에서 "왜 이 모델이냐"에 답할 수 없다.

## 기록 규칙

- 번호: E-001부터. 한 실험 = 한 가설(설계 `docs/design/modeling-v1.md` 7-1의 `H-NN`).
- 모든 실험은 walk-forward 평가 결과만 적는다. 무작위 분할 결과는 기록하지 않는다(의미가 없다).
- 항상 같은 경기 집합에 대해 기준선(홈팀 승 / 시즌 승률 / Elo)과 나란히 적는다. 실험 간 비교는 `presagio backtest compare`(공통 경기 집합 + 짝 부트스트랩)로 낸다.
- 재현에 필요한 것: 코드 커밋 해시, 피처 버전, 학습 기간, 시드, 하이퍼파라미터, 실행 명령 한 줄.
- **사전 등록:** 가설·비교 대상·사전 판정 기준·경기 집합·실행 명령을 결과를 보기 **전에** 이 문서에 적고 main에 머지한다(상태 `등록(미실행)`). 결과는 그 뒤 다른 PR에서 채운다. 판정 기준 문장은 결과를 본 뒤 바꾸지 않는다(바꿔야 하면 새 번호로 다시 등록, 설계 7-1).
- **표본 부족:** 판정에 쓰는 비교의 n < 100이면 숫자는 "참고(표본 부족)"로 적고 판정을 보류한다(설계 4-6).
- **보고 시즌 1회:** 2024-25 판정 비교는 가설마다 사전 등록된 비교 **한 번**만 돌린다. 다시 돌려 고르지 않는다. 추가로 돌린 것은 `exploratory`로 표시하고 선택 근거로 쓰지 않는다(설계 6-4).
- **보류 시즌(2025-26):** 열지 않는다. 연 경우에는 해제 사유와 몇 번째 해제인지를 적는다(설계 6-3).

## E-001 H-01: 문헌 출발 상수의 Elo(B2) vs 항상 홈(B0)·시즌 승률(B1)
- **상태:** 등록(미실행)
- **가설 번호:** H-01
- **날짜:** 등록 2026-11-10 / 실행 —
- **가설:** 문헌 출발 상수의 Elo(B2)는 항상 홈(B0)·시즌 승률(B1)보다 확률 품질이 좋다
- **비교 대상:** B2 vs B0, B1
- **지표:** log loss, Brier, 정확도
- **사전 판정 기준:** `LL_B2 ≤ LL_B0 − 0.02` **그리고** `Brier_B2 ≤ Brier_B0 − 0.005` **그리고** `acc_B2 ≥ acc_B1`. 하나라도 어기면 구현을 먼저 의심(감사)
  - 판정 방법(등록 시 정함): 세 항목을 각각 `판정: 충족 / 미충족`으로 적는다. 판정 구간은 **2024-25 전체**(`2024-25 | all` 행). 2023-24 후반(2024-01-01 이후 = 보고 대상, `2023-24 | all` 행)은 참고. `LL_B2 − LL_B0`·`Brier_B2 − Brier_B0`는 `--reference B0` 출력의 B2 행 `dLL`·`dBrier`(점추정과 90% 구간을 함께 적는다), `acc_B2 − acc_B1`은 `--reference B1` 출력의 B2 행 `dAccuracy`. 하나라도 미충족이면 승패를 선언하지 않고 "구현 의심 → 감사 요청"으로 적는다.
- **실험군:** 시장 미포함
- **평가 데이터(설계 7-1):** 2024-25 전체 + 2023-24 후반(참고)
- **경기 집합:** 2023-24·2024-25의 정규·플레이인·플레이오프 경기 중 B0·B1·B2 모두에서 보고 대상(2024-01-01 이후)이고 종료·채점되고 `p_home`이 있는 `(game_id, as_of)`의 교집합(`backtest compare`의 공통 경기 집합). `market_status` 무관(시장 미포함 실험군 = 설계 4-6 (a) 전체 경기). n은 출력 머리말의 `Common game set … n =`과 구간별 n 열.
- **실행할 명령(PR B):**
  - `uv run presagio backtest compare --experiments B0,B1,B2 --reference B0 --seasons 2023-24,2024-25`
  - `uv run presagio backtest compare --experiments B0,B1,B2 --reference B1 --seasons 2023-24,2024-25`
- **불확실성:** 위 `dLL`·`dBrier` 열의 90% 짝 부트스트랩 구간(한 구간 안의 모든 실험이 같은 재표집 경기를 쓴다).
- **참고 줄:** 구간마다 `always home (= home win rate)` 줄(설계 5-1 "항상 홈 승" 정확도, D-055 6항). B0의 정확도(p ≥ 0.5 규칙)와 다를 수 있다.
- **결과:** (PR B)
- **결론 / 다음에 할 것:** (PR B)

## E-002 H-03: 예측 시점 시장(B3) vs Elo(B2)
- **상태:** 등록(미실행)
- **가설 번호:** H-03
- **날짜:** 등록 2026-11-10 / 실행 —
- **가설:** 예측 시점 시장 확률(B3)은 Elo(B2)보다 낫다 — "시장이 가장 강한 기준선"의 확인
- **비교 대상:** B3 vs B2, 그리고 B4(마감) vs B3
- **지표:** log loss, Brier, Δ
- **사전 판정 기준:** 확인 조건: `LL_B3 ≤ LL_B2 − 0.01`. **거꾸로**(`LL_B2 < LL_B3`)면 승리 선언이 아니라 **누수·매핑 버그 감사 먼저**. 보조: `LL_B4 ≤ LL_B3`(마감이 더 정보가 많다)
  - 판정 방법(등록 시 정함): 주 판정은 `compare --reference B2` 출력에서 2026-27 전체 행(포스트시즌이 없으면 `2026-27 | regular` 행, 있으면 `2026-27 | all` 행)의 B3 `dLL`(= `LL_B3 − LL_B2`)이 `≤ −0.01`이면 충족. `dLL > 0`(B2가 더 낫다)이면 "누수·매핑 버그 감사 먼저"로 적고 결론을 내지 않는다. 보조는 `backtest run --experiment B3` 출력의 "vs closing market B4" 표 `dLL`(= `LL_B3 − LL_B4`, `available`만)이 `≥ 0`이면 충족. 각 비교의 n < 100이면 "참고(표본 부족)", 판정 보류.
- **실험군:** 시장 포함
- **평가 데이터(설계 7-1):** 주 판정(B3 vs B2): `market_status IN ('available', 'pred_only')`. 보조(B4 vs B3): `available`. 각각 같은 경기 집합 안에서 비교(4-6)
- **경기 집합:** 2026-27(실시간 시즌을 백테스트 as_of로 재현) 종료 경기 중 B2·B3 모두 보고 대상·채점·`p_home` 있음이고 `market_status`가 `available` 또는 `pred_only`인 `(game_id, as_of)`(B3가 들어가면 `compare`가 자동으로 이 집합(4-6 (b))으로 좁힌다). 보조는 같은 시즌 B3 예측 중 `available`.
- **실행할 명령(PR B):**
  - `uv run presagio backtest compare --experiments B2,B3 --reference B2 --seasons 2026-27`
  - `uv run presagio backtest run --experiment B3 --seasons 2026-27`
- **알려진 제약(등록 시 이미 아는 것):** 2026-27 n은 100 경계다(2026-11-10 PM 확인: 종료 154경기 중 예측 시점 스냅숏이 있는 경기 약 100). 백테스트 as_of 07:00:00 UTC는 그날 A0 배당 캡처(07:00 직후)를 보지 못해 B3가 전날 캡처를 쓴다 — 정보가 적은 쪽이라 B3에 보수적이다(Q-025, D-065 5항).
- **결과:** (PR B)
- **결론 / 다음에 할 것:** (PR B)

## E-003 H-04(a): 네스티드로 고른 Elo 상수(K·HCA·carry) vs 538 출발값
- **상태:** 등록(미실행)
- **가설 번호:** H-04 (이 항목은 (a)만. (b) MOV는 E-004, 보류)
- **날짜:** 등록 2026-11-10 / 실행 —
- **가설:** 네스티드로 고른 Elo 상수(K·HCA, DR-1이 있으면 carry)와 점수 차 배수(MOV)는 538 출발값보다 2024-25에서 낫다
- **비교 대상:** (a) 격자 최적(2023-24) vs K=20/HCA=100/carry=0.75, (b) (a)의 결과 위에 MOV 유무
- **지표:** log loss
- **사전 판정 기준:** (a) 채택 조건 `LL_튜닝 ≤ LL_출발 − 0.005`(2024-25), 아니면 출발값 유지. (b) MOV는 추가로 `≤ −0.005` 개선 시 채택(식은 1차 출처 확인 뒤, 5-2). carry는 DR-1 없으면 0.75 고정(6-4)
  - 판정 방법(등록 시 정함): 이 항목은 (a)만 판정한다. DR-1(2022-23, P-026)이 적재돼 있으므로 carry도 탐색한다. 판정은 마지막 `compare` 출력의 `2024-25 | all` 행에서 튜닝 설정의 `dLL`(= `LL_튜닝 − LL_출발`)이 `≤ −0.005`면 충족(채택), 아니면 미충족(출발값 유지). 이 비교는 **한 번만** 돌린다. 격자 최적 칸이 출발값 칸이면 비교는 Δ 0으로 미충족이다.
- **실험군:** 시장 미포함
- **평가 데이터(설계 7-1):** 선택 2023-24, 판정 2024-25
- **경기 집합:** 선택 — K·HCA는 2023-24의 2024-01-01 이후 경기(설계 6-4), carry는 2023-24 개막(2023-10-24)부터의 경기(2022-23 → 2023-24 시즌 경계 효과가 시즌 초에 있으므로, PM 결정). `grid`는 선택 시즌만 예측·채점하고 다른 시즌의 지표를 출력하지 않는다. 판정 — 2024-25 정규·플레이인·플레이오프 중 두 설정 모두 채점된 `(game_id, as_of)`(공통 경기 집합).
- **실행할 명령(PR B, 순서대로):**
  1. `uv run presagio backtest grid --experiment B2 --param k=10,15,20,25,30 --param hca=50,75,100,125 --select-season 2023-24 --select-from 2024-01-01` → 최적 칸 (K*, H*)
  2. `uv run presagio backtest grid --experiment B2 --param carry=0.6,0.75,0.9 --fixed k=K*,hca=H* --select-season 2023-24 --select-from 2023-10-24` → C*
