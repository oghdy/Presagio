# 리스크와 대응책

> "회사 구조"로 일할 때 생기는 위험과, 원래 프로젝트가 가진 위험을 모두 적는다.
> 각 항목은 **위험 → 왜 생기나 → 대응(누가, 어떻게) → 그래도 터지면** 순서다.

## A. 회사 구조(멀티 에이전트)에서 생기는 위험

### A1. 에이전트가 기억을 잃어서 맥락이 끊긴다
- **왜:** 세션마다 기억이 새로 시작된다. "아까 얘기한 거"가 통하지 않는다.
- **대응:**
  - 모든 상태를 문서에 둔다: backlog(할 일), decisions(결정), experiments(실험), PR 본문(결과).
  - 브리핑은 처음 보는 사람 기준으로 쓴다(`handoff-templates.md` B).
  - 세션 시작 시 읽을 파일 순서를 역할 파일마다 고정했다.
- **그래도 터지면:** PM이 해당 티켓을 반려하고 브리핑에 빠진 맥락을 추가해서 다시 띄운다. 빠진 맥락은 decisions.md나 티켓 메모에 영구히 적는다.

### A2. 토큰 비용이 폭발한다
- **왜:** 역할이 많을수록 같은 파일을 여러 번 읽고, 핸드오프마다 설명이 반복된다.
- **대응:**
  - 단계별 역할 활성화. 단계 0~1은 PM, Data Engineer, Reviewer 셋만.
  - 리뷰어에게는 diff와 티켓만 준다. 전체 히스토리를 주지 않는다.
  - 조사만 하는 일(탐색, 문서 읽기)은 싼 모델의 서브에이전트에 맡긴다. Scribe는 `sonnet`.
  - 티켓을 작게 유지한다(변경 파일 10개 이하). 큰 티켓은 세션이 길어져 비용과 실패율이 함께 오른다.
- **그래도 터지면:** PM 세션이 너무 길어지면 "단계 종료 학습 노트"를 쓰고 PM 세션을 새로 띄운다. 문서에 상태가 다 있으므로 가능하다.

### A3. 사람이 코드를 이해하지 못하게 된다 (포트폴리오로서 치명적)
- **왜:** 에이전트가 다 짜면 면접에서 "왜 이렇게 했냐"에 답을 못 한다.
- **대응:**
  - 모든 PR에 "이 PR을 3문장으로" 섹션 필수. 쉬운 말로.
  - 사람은 머지 전에 PM에게 질문 1개 이상. 수락 메시지에 "네가 물어볼 만한 질문"을 PM이 미리 넣는다.
  - 단계 종료마다 학습 노트 + 면접 예상 질문 3개. `docs/learning/glossary.md`에 용어를 쌓는다.
  - 결정 기록에 반드시 "다른 선택지와 안 고른 이유"를 쓴다. 면접 질문은 거기서 나온다.
- **그래도 터지면:** 사람이 이해 못 한 PR은 머지하지 않고 PM에게 "더 쉽게 설명해 달라"고 요청한다. 이해가 머지 조건이다.

### A4. 두 세션이 같은 파일을 동시에 고쳐서 덮어쓴다
- **왜:** worktree 없이 같은 폴더에서 두 작업자가 돌면 한쪽 변경이 사라진다.
- **대응:**
  - 작업자는 항상 자기 worktree(브랜치)에서 일한다.
  - `CLAUDE.md` 5장의 파일 소유권 표. 영역당 작업자는 한 명.
  - 같은 영역 티켓은 PM이 순서대로만 띄운다.
- **그래도 터지면:** git 충돌로 드러난다. PM이 나중 티켓을 반려하고 main 기준으로 다시 따게 한다.

### A5. 작업자가 완료 기준을 스스로 느슨하게 해석한다
- **왜:** 모델은 "거의 됐다"를 "됐다"로 보고하는 경향이 있다.
- **대응:**
  - 완료 기준은 검증 가능한 문장으로만 쓴다(명령 + 예상 결과).
  - 리뷰어가 명령을 **직접 실행**한다. PR 본문의 주장은 믿지 않는다.
  - 기준 변경은 사람만 할 수 있다. 작업자와 PM은 못 바꾼다.
- **그래도 터지면:** 리뷰어 보고서에서 X가 나오면 반려. 반려 2회면 티켓을 쪼갠다.

### A6. 리뷰어가 작성자 의견에 끌려간다 (앵커링)
- **왜:** "이렇게 결론냈어, 맞지?"라고 물으면 모델은 대개 "맞다"고 한다.
- **대응:** 리뷰어는 PR마다 새 세션. 작성자 결론과 PM 의견을 주지 않는다. 코드와 티켓만 준다.
- **그래도 터지면:** 사람이 머지 전 질문에서 걸러낸다.

### A7. 같은 실패를 무한 반복하는 세션
- **왜:** 환경 문제(미설치 도구, 네트워크 차단)를 코드 문제로 오해하고 계속 고친다.
- **대응:** "같은 실패 2회면 멈추고 보고" 규칙을 모든 역할 파일에 넣었다. 환경 문제는 티켓 메모에 적어 다음 작업자가 반복하지 않게 한다.
- **그래도 터지면:** 사람이 세션을 멈추고 PM에게 상황을 넘긴다.

### A8. 추측으로 라이브러리를 쓴다
- **왜:** 모델은 기억에 있는 API 모양을 그대로 쓰는데, 버전이 바뀌었을 수 있다.
- **대응:** PR 본문에 "확인한 외부 동작" 섹션 필수. 실제 호출 결과 샘플을 `tests/fixtures/`에 저장. 리뷰어 체크리스트에 포함.
- **그래도 터지면:** 테스트가 실패하거나 리뷰어가 잡는다.

### A9. PM 세션 자체가 길어져 느려지고 헷갈린다
- **왜:** PM은 장기 세션이라 컨텍스트가 계속 쌓인다.
- **대응:** 단계가 끝나면 PM 세션을 새로 띄운다. backlog, decisions, 학습 노트만 있으면 새 PM이 이어받을 수 있게 설계했다.

## B. 프로젝트 자체의 위험 (PRESAGIO_OVERVIEW 10장을 구체화)

### B1. nba_api 차단, 속도 제한, 응답 형식 변경
- **대응(Data Engineer):**
  - 공통 HTTP 레이어: 요청 간 딜레이(기본 0.6초 이상), 지수 백오프 재시도 3회, 타임아웃 10초. 이 값들은 설정으로 뺀다.
  - 모든 응답을 `raw_api_responses`에 저장. 형식이 바뀌어도 raw에서 다시 정제할 수 있다.
  - 소스별 어댑터 분리. 어댑터 인터페이스(`fetch_schedule(date)`, `fetch_boxscore(game_id)` 같은 함수)만 지키면 소스를 바꿀 수 있다.
  - 백필은 날짜 단위로 재개 가능하게. 중간에 끊겨도 다시 돌리면 이어서 한다(멱등성).
- **그래도 터지면:** 단계 1 티켓 P-010에서 대체 소스 후보를 같이 조사해 둔다.

### B2. 배당 데이터 무료 한도 부족
- **대응(PM이 사람에게 결정 요청):** 후보 API의 무료 한도, 과거 데이터 제공 여부, 약관을 표로 정리(P-018). 수집 빈도를 하루 2회(예측 시점, 마감 직전)로 제한. 과거 배당은 구할 수 있는 범위만 쓰고, 없는 기간은 "시장 비교 불가"로 정직하게 표시.

### B3. 데이터 누수로 성능이 부풀려진다
- **대응(ML Engineer + Leakage Auditor):** `as_of` 강제, 시간 여행 테스트, 미래 데이터 주입 테스트, walk-forward만 허용. 작성자 ≠ 검증자 구조. 배당은 "예측 시점"과 "마감"을 따로 저장.

### B4. 과적합
- **대응(ML Engineer):** 항상 단순 기준선(홈팀 승, 시즌 승률, Elo)과 비교. 시즌 단위 walk-forward. 피처 수를 기록하고 늘릴 때 근거를 experiments.md에 남긴다.

### B5. 결측/이상 데이터
- **대응(Data Engineer):** 품질 체크 모듈(P-020): 경기당 두 팀 레코드, 팀 득점 합 = 최종 점수, 날짜 범위 내 경기 수 상식 범위. 실패는 `ingestion_runs`에 기록하고 멈추지 않고 다음 날짜로 진행(실패 목록은 보고).

### B6. 비밀값 커밋
- **대응:** `.gitignore`에 `.env`. `.env.example`에는 가짜 값만. 단계 0에서 pre-commit에 비밀값 탐지 훅(gitleaks 또는 detect-secrets) 추가(P-001). 리뷰어 체크리스트 포함.

### B7. 범위가 커져서 끝이 안 난다
- **대응:** 단계별 완료 기준을 사람만 바꿀 수 있다. 새 아이디어는 backlog의 "나중에(단계 7)" 구간에만 적는다. PM은 현재 단계 티켓이 모두 DONE이기 전에 다음 단계 티켓을 띄우지 않는다.

### B8. 개발 환경 문제 (현재 알려진 것)
- `uv`가 이 맥에 설치되어 있지 않다(2026-10-21 확인). P-001에서 설치부터 한다.
- Python은 anaconda 경로의 것이 잡힌다. 프로젝트는 uv가 관리하는 3.12 가상환경을 쓴다. 시스템 파이썬에 의존하지 않는다.
